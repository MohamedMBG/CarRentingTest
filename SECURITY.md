# Security & Secrets Hygiene

This document describes how secrets, signing keys, and environment-specific configuration
are handled in this repository. **No real secret value belongs in source control.**

---

## 1. Firebase configuration (`google-services.json`)

### Status
The file `app/google-services.json` is **gitignored** and must be provisioned per-environment.
A sanitized template lives at `app/google-services.json.example`.

### Why
The Google Services file contains:
- Firebase Web/Android API key (`api_key.current_key`)
- Mobile SDK App ID (`mobilesdk_app_id`)
- Project number, storage bucket, and package name

Although the Android API key is referrer-restricted on Google's side, leaking it in a
public repo enables abuse, Firebase project enumeration, and triggers Google secret-scan
alerts.

### Rotation (required — past leak)
The previous tracked file exposed key `AIzaSy...zCRk` (now in git history). Action items:

1. Open [Google Cloud Console → APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials)
   for project `carrentingtest`.
2. Locate the **Android key** referenced in the leaked file. **Delete** or **regenerate** it.
3. In [Firebase Console → Project Settings → Your apps](https://console.firebase.google.com/),
   re-download the new `google-services.json`.
4. Place it at `app/google-services.json` (gitignored).
5. (Recommended) Restrict the new key by Android package name + SHA-1 in GCP Console.
6. Purge the secret from git history with [`git filter-repo`](https://github.com/newren/git-filter-repo)
   or BFG **after** all collaborators have rebased. (History rewrite is destructive — coordinate first.)

### Local developer setup
```
# After cloning:
cp app/google-services.json.example app/google-services.json
# Then replace placeholders with values from Firebase Console.
```

### CI injection
Store the full file contents as an encrypted CI secret named `GOOGLE_SERVICES_JSON`.

**GitHub Actions example:**
```yaml
- name: Write google-services.json
  run: |
    printf '%s' "${{ secrets.GOOGLE_SERVICES_JSON }}" > app/google-services.json
- name: Build
  run: ./gradlew assembleRelease
```

**Bitrise / GitLab / Jenkins:** equivalent — write the secret to `app/google-services.json`
before invoking gradle. Never echo the contents in logs.

## 2. Application ID (Play Store package name)

### Status
`applicationId` is now driven by gradle property `APPLICATION_ID`. Default remains
`com.example.carrentingtest` to keep dev builds working. Release builds **fail** if the
default is still in effect.

### Why
`com.example.*` is an unowned namespace; the Play Store will not let you upload under it
in production, and squatters can register the id ahead of you.

### Setting the real id

Choose a brand-owned domain you control (reverse-DNS). Examples (do not use literally):
`com.bbluxurycars.app`, `ma.bbluxury.carrenting`.

Then set it in any **one** of these places (precedence in order):

1. `-PAPPLICATION_ID=com.yourbrand.carrenting` on the gradle command line
2. Environment variable `APPLICATION_ID=com.yourbrand.carrenting`
3. `local.properties`:
   ```
   APPLICATION_ID=com.yourbrand.carrenting
   ```

### Follow-up tasks (not in this PR)
- Rename the Java package `com.example.carrentingtest.*` → new namespace (refactor across
  ~96 source files plus `AndroidManifest.xml`, `namespace` in `build.gradle.kts`, and
  `package_name` in `google-services.json`).
- Re-register the Android app in Firebase under the new package name and download a fresh
  `google-services.json`.
- Generate a new release signing key for the new id; never reuse the debug keystore.

## 3. Backend configuration (`BACKEND_BASE_URL`)

### Status (audit confirmed)
`BACKEND_BASE_URL` enters the build through exactly one channel — `readStringConfig` in
`app/build.gradle.kts:26` — which resolves it in this order:

1. Gradle property (`-PBACKEND_BASE_URL=...` or `gradle.properties`)
2. Environment variable
3. `local.properties`

Java code reads only `BuildConfig.BACKEND_BASE_URL` (`network/BackendClient.java:106`).
**No URL is hardcoded anywhere** in source.

### Release-build guards (in `app/build.gradle.kts`)
- Must be set (non-blank).
- Must start with `https://`.
- Cleartext traffic is disabled in `manifestPlaceholders` for release.

### Recommended dev value
Put in `local.properties` (gitignored):
```
BACKEND_BASE_URL=https://api.staging.your-backend.example
```

## 4. `local.properties` and `.env` audit

- `local.properties` — gitignored (`.gitignore:3` and `.gitignore:15`). Currently contains
  only `sdk.dir`. Safe.
- No `.env` files exist in the repo. `.env`, `.env.*` are now gitignored as a guard.

## 5. Signing keys

- Debug keystore: auto-generated by AGP, not in repo. OK.
- Release keystore: **do not commit**. Inject via CI secrets and reference via
  `signingConfigs` reading from env vars when release signing is wired up.

---

## Quick checklist before tagging a release

- [ ] `app/google-services.json` present locally / injected in CI from `GOOGLE_SERVICES_JSON` secret.
- [ ] `APPLICATION_ID` set to real brand domain (not `com.example.*`).
- [ ] `BACKEND_BASE_URL` set, HTTPS, points to prod backend.
- [ ] Old leaked Firebase API key rotated and restricted.
- [ ] Release keystore loaded from secret, not tracked.
